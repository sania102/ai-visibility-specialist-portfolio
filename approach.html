Implementation notes

A technical foundation for clear discovery.

AI visibility is not a single markup trick. This demonstration focuses on fundamentals: accessible content, stable URLs, crawl access, descriptive metadata and structured entities.

01 / Page structure

Make the content understandable.

What is implemented

  • One descriptive H1 per page and logical section headings.
  • Semantic header, navigation, main, section, article and footer elements.
  • Useful visible text that agrees with the page metadata and schema.
  • Responsive layout and accessible navigation labels.

Why it matters

Clear information architecture helps people and automated systems identify the topic, sections and relationships on a page. Structured data should reinforce the visible page, not contradict it.

02 / Crawlability

Remove avoidable discovery friction.

Canonical URL

Each page declares its preferred URL to reduce ambiguity about the canonical page.

Robots directives

A simple robots.txt allows public crawling and points crawlers to the sitemap.

XML sitemap

The sitemap lists the public pages included in this small portfolio site.

03 / AI discovery

Provide useful, direct context.

The site includes an llms.txt file as an optional human-readable project summary for AI-oriented tooling. It is an emerging convention, not a guaranteed ranking or crawling mechanism. Core discoverability still depends on accessible pages, sound technical implementation and the policies of each crawler.

No website markup can guarantee inclusion, citation or ranking in ChatGPT, Perplexity, Google or any other search product.
